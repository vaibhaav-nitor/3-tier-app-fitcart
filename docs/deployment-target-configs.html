Infrastructure reference

What else can be configured — AKS, App Service, and a VM

Provisioning options for each compute target, and the deployment-time options once the app is actually running on it. Grouped the same way across all three so they're easy to compare.

The AKS column reflects real gaps checked against this repo's terraform/modules/aks/main.tf and Helm charts — no network_policy, no diagnostic settings, no securityContext on any pod today. App Service and VM are general Azure practice — this repo currently has no VM deployment and the App Service module lives on a different branch.
AKS (Kubernetes) Azure App Service Virtual Machine
Kubernetes

AKS cluster

Provisioning the cluster

Networking

network_policy
Azure NPM or Cilium. Without it, any NetworkPolicy manifest is accepted but never enforced.
authorized_ip_ranges / private_cluster
Restrict or remove the public API server endpoint.

Identity

local_account_disabled
Forces Azure AD auth for kubectl access instead of the static admin cert.
oidc_issuer_enabled
Workload identity — pods get Azure credentials without long-lived secrets.

Scaling

enable_auto_scaling
Min/max node count, instead of the fixed node_count this module uses today.
additional node pools
Separate system and user pools, or a spot pool for non-critical workloads.

Observability

oms_agent / Container Insights
Diagnostic settings to Log Analytics — currently nothing captures control-plane or pod logs centrally.

Resilience

zones
Spread the node pool across availability zones.
automatic_channel_upgrade
Patch/node-image cadence, paired with a maintenance window.

Security

azurepolicy add-on
Gatekeeper-based admission policies (Azure Policy for AKS) — enforced cluster-wide, not just per-namespace.
Defender for Containers
Image scanning at pull time plus runtime threat detection.
disk_encryption_set_id
Customer-managed keys for node OS/data disk encryption, instead of the platform-managed default.

Deploying the app onto it

Identity & secrets

SecretProviderClass
Key Vault CSI driver, mounting secrets directly instead of passing them through helm --set.
serviceAccountName
A minimal, dedicated account per tier; automountServiceAccountToken: false where the API is never called.

Networking

NetworkPolicy per tier
Frontend public on 80, backend only from frontend, database only from backend — see docs/network-policy.md. Needs the network_policy engine above to actually enforce.
Ingress + cert-manager
Replaces the frontend's bare LoadBalancer Service with a real hostname and managed TLS.
hostAliases
Manual DNS override on a pod — rarely needed, but worth knowing about if a service must resolve a name outside cluster DNS.

Security

securityContext
Non-root user, read-only root filesystem, dropped capabilities — none of the three Deployments set this today.
ResourceQuota / LimitRange
Namespace-wide caps so one bad --set can't request more than a node has.
ephemeral-storage limit
Nothing today caps how much a pod can write to its writable layer.
emptyDir for /tmp
Pairs with readOnlyRootFilesystem — nginx and the JVM both need somewhere writable, just not the root filesystem.

Scheduling

nodeSelector / tolerations
Pin a component to a specific node pool — e.g. a dedicated pool for the database.
podAntiAffinity
Keeps replicas of the same service off the same node.
priorityClassName
Protects a critical pod (the database) from being the one evicted under node pressure.

Lifecycle

terminationGracePeriodSeconds + preStop
Lets the backend finish in-flight requests before the pod is killed.
startupProbe
Fits a slow-starting JVM better than guessing initialDelaySeconds on the readiness probe.

Scaling & resilience

HorizontalPodAutoscaler
Replaces the static replicaCount.
PodDisruptionBudget
minAvailable: 1, so a node drain can't take out every backend replica at once.
topologySpreadConstraints
Spreads replicas across nodes instead of letting the scheduler stack them.

Observability

prometheus.io/scrape annotations
Or a ServiceMonitor, if using the Prometheus Operator — ties into the actuator/Micrometer work already on feature/managed-db.
downward API env vars
fieldRef: metadata.name / status.podIP, for structured logs that can be traced back to a pod.

Deployment mechanics

image digest pinning
image@sha256:... instead of a mutable tag like latest.
imagePullPolicy: Always
Specifically where a mutable tag is still in use — IfNotPresent on latest can keep serving a stale cached image.
maxSurge / maxUnavailable
Tunes the rolling update instead of the chart defaults.
initContainers
A wait-for-Postgres check, or a dedicated schema-migration step, ahead of the main container starting.
PaaS

App Service

Provisioning the plan & web apps

Networking

vnet_integration
Routes the web app's outbound traffic through your VNet — needed to reach a database on a private endpoint.
ip_restriction
Access-restriction rules on the app, instead of a fully public endpoint.

Identity

identity { type = "SystemAssigned" }
Lets the app authenticate to Key Vault without a client secret.
auth_settings_v2
Easy Auth — Azure AD sign-in enforced in front of the app itself.

Scaling

autoscale_setting
CPU/memory or schedule-based rules on the Plan.
Premium v3 tier
Needed for zone-redundant deployment.

Observability & resilience

Application Insights
Linked at creation, rather than added later by hand.
deployment slots
A staging slot for validation and slot-swap releases.
backup block
Scheduled app + database backup to storage.

Security

minimum_tls_version
Pin to 1.2, and disable FTP/basic auth publishing credentials.

Deploying the app onto it

Identity & secrets

@Microsoft.KeyVault(...)
App settings resolved as Key Vault references, backed by the managed identity above.

Networking

custom domain + managed cert
Rather than the default *.azurewebsites.net hostname.
https_only
Enforces the HTTP→HTTPS redirect.

Scaling & resilience

health_check_path
Used both for load-balancing between instances and for auto-heal.
always_on
Stops the app unloading after idle, which otherwise shows up as a slow first request.

Deployment mechanics

slot swap
Blue/green release instead of deploying straight to production.
startup command
Overrides the container entrypoint per app setting, without rebuilding the image.
IaaS

Virtual machine

Provisioning the VM

Networking

network_security_group
Rules scoped to the exact ports the app needs — not a broad allow.
Azure Bastion
Replaces a public SSH/RDP endpoint entirely.
Just-In-Time access
Opens the management port only for a requested window, via Defender for Cloud.

Identity

identity { type = "SystemAssigned" }
Used to pull secrets at boot instead of baking them into the image.
disable_password_authentication
SSH key only.

Scaling & resilience

Virtual Machine Scale Set
Instead of a single VM — this is what actually makes autoscaling and rolling patching possible.
availability zone
Or an availability set if zones aren't an option in the region.
Azure Update Manager
Scheduled patching instead of manual apt/yum upgrade.

Observability & security

boot_diagnostics
Serial console output, useful when the app never comes up.
Azure Monitor Agent + DCR
Ships OS and app logs to Log Analytics.
disk encryption
Azure Disk Encryption on the OS and data disks.

Deploying the app onto it

Identity & secrets

managed-identity Key Vault pull
Fetched at boot via cloud-init, never stored in the VM image.

Networking

nginx reverse proxy
Sits in front of the app; the NSG allows inbound only to the proxy, not the app port directly.

Security

dedicated system user
The app runs as its own non-root account, never as root.
systemd sandboxing
ProtectSystem=strict, NoNewPrivileges=true on the unit file.

Deployment mechanics

immutable image (Packer)
Versus config-management push — decide once, since it changes how every future release ships.
rolling instance refresh
Across the scale set, so a bad release doesn't hit every instance at once.
health-checked load balancer
App-level health endpoint the LB polls before sending traffic to an instance.
